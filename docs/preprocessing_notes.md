# Замечания к ноутбуку 01

Код подготовки данных оставлен в исходном виде — он рабочий и решает свою задачу. Ниже то, что стоит поправить, если возвращаться к нему. Ничего из этого не применено в `01_data_preparation.ipynb`; всё, что понадобилось для дальнейшего анализа, сделано в `02_cleaning_and_features.ipynb`.

## Незамапленные значения теряются молча

Для курсов есть страховка:

```python
assert df['course_group'].isna().sum() == 0, "есть незамапленные курсы"
```

Для типа оплаты такой проверки нет, и значение `Downpayment` в словарь не попало. В результате 101 строка получает пустую группу, и узнать об этом можно только вручную посмотрев на `value_counts`. Стоит закрыть все словари одинаковыми проверками — иначе новая категория в выгрузке пройдёт незамеченной.

С каналами похожая история наоборот: `.fillna('other')` подхватывает не только настоящие пропуски, но и любое новое значение, которого нет в словаре. Работает, но новые каналы будут тихо утекать в `other`.

## `Undefined` склеен с внутренней рассрочкой

```python
'Undefined': 'internal_installment'
```

`Undefined` означает «тип оплаты не определён», а не «внутренняя рассрочка». По поведению это разные группы: в исходной выгрузке у `Undefined` конверсия во второй курс 1.5% против 44.6% у внутренней рассрочки. Склейка размывает одну из самых сильных категорий в данных. Лучше вынести в отдельную группу или удалить.

## Две строки не делают ничего

```python
df['course_format_group'] = df['course_format'].map(format_map)
df['course_format_group'].astype('category')
```

`astype` возвращает новый объект, а не меняет колонку на месте. Результат никуда не присваивается, тип остаётся `object`. То же самое со следующей ячейкой для `payment_type_group`. Ошибка безобидная — в срезе `data` типы позже проставляются заново, — но сами строки лучше убрать или дописать присваивание.

## Уникальность ключа не проверяется

`index_col=0` делает идентификатор индексом, но никто не проверяет, что он уникален. В выгрузке нашлась одна пара строк с одним идентификатором, одинаковой датой старта и разным рейтингом. Одна строка на 7 295 погоды не делает, но проверку стоит держать в пайплайне.

## Возраст заполняется до фильтрации выборки

```python
df['age'] = df.groupby('course_group')['age'].transform(lambda x: x.fillna(x.median()))
```

Медиана считается по всем строкам выгрузки, включая старты 2023, 2025 и 2026 годов, которые в анализ потом не идут. Разница небольшая, но правильнее сначала отобрать когорту, а потом восстанавливать пропуски.

Тот же groupby выдаёт `FutureWarning` про `observed`, потому что `course_group` уже приведён к категориальному типу. Лечится явным `observed=True`.

## Срез теряет `group_id`

В `data` не попадает `group_id`, хотя без него нельзя восстановить размер учебной группы — а он нужен, чтобы нормировать рейтинг. В ноутбуке 02 приходится работать с полным датафреймом. Стоит либо добавить колонку в срез, либо не делать срез вовсе.

## Магические числа

Границы возраста `5` и `17`, число `50` в `value_counts().head(50)` и порог `17` в формуле для `[13+]` зашиты в код напрямую. Их стоит вынести в константы наверх — тогда правило будет видно с одного взгляда и не придётся искать по ячейкам.
